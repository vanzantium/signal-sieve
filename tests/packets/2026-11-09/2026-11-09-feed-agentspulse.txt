COVERAGE — AgentsPulse, "Claude Dreaming: How Anthropic's Dreams Fixes Agent Memory"
URL: https://agentspulse.github.io/tutorials/claude-dreaming/
Published: 2026-11-07 (last updated 2 days ago as of 2026-11-09).

Anthropic has added Claude dreaming to Claude Managed Agents. The new Dreams endpoint takes an agent's memory store and up to 100 of its past sessions, and writes a reorganized memory store with duplicates merged, contradictions resolved and stale entries replaced. On November 6, 2026, Anthropic published the research behind it, "The components of agent memory", with test results on benchmarks, Pokemon Red and document wikis. Dreams is a research preview. You request access, and it runs only on the Claude API.

A dream is an asynchronous job: you pass a memory store and a list of sessions, and you get back the ID of a new memory store when it finishes. Requests need two beta headers, managed-agents-2026-04-01 and dreaming-2026-04-21. Inputs: one existing memory store and between 1 and 100 sessions. The input store is never changed; the output is always a new store. The docs list Haiku 5.5, Haiku 4.5, Opus 4.6, Opus 4.5, Sonnet 4.5 and the Mythos models as unsupported. A dream moves through pending, running, completed, failed or canceled. The docs say it can take from a few minutes to a few hours. A failed or canceled dream still leaves a partial output store.

Dreams has no separate fee. According to the docs, it bills at the standard token rates of the model you choose, and cost scales roughly linearly with the number and length of sessions. Other limits: research preview, access by request; Claude API only; not eligible for Zero Data Retention or HIPAA; listing dreams returns 20 by default and at most 100.

The Dreams docs link to a Claude Cookbook recipe by Brad Abrams, published November 2, 2026, for teams that want to control the prompts, models and schedule themselves. The cookbook's example costs at list price: 11 example transcripts (283 KB) cost $0.36 and took about 2.5 minutes; 50 long transcripts (about 12 MB) with cost-saving settings cost about $8 and took about 10 minutes; the same 50 without those settings cost about $10 and took about 9 minutes. Its default budget ceiling is $40 per run. The recipe treats transcripts as untrusted input: analyzers get file tools only, with no shell, no web and an empty network allowlist, and the dreaming session is the only place the store is mounted read-write.

Results (all numbers are Anthropic's internal runs): on the CL-Bench 1.0 database task, Opus 5.5 0.838 vs 0.655, Sonnet 5.5 0.833 vs 0.644, Opus 5 0.828 vs 0.564, Opus 4.7 0.700 vs 0.383, Sonnet 5 0.610 vs 0.306, Sonnet 4.6 0.364 vs 0.330. This chart measures memory notes, not dreaming. Opus 5 rose from 0.564 to 0.828 and was the first to close the loop. Sonnet 4.6 barely moved (0.330 to 0.364) until prompted to read its memory and test its theories, which took it to 0.641. Telling models to "record only failures" cut the gain from memory by 0.234 for Opus 5 and 0.150 for Opus 4.7.

Pokemon: with the corrected note, Claude went back into the cave and reached Cerulean City at action 1,935. The run with the uncorrected note fell off the ledge three times and ended back in Pewter City. These are single runs, so they show the mechanism rather than a success rate.

Wiki: Anthropic tested wikis on about 350,000 internal files (roughly 420M tokens) from Stainless, using 25 questions. Opus 5 agents dreamed over 128 sessions. Wiki alone, after 2 sessions: 13%. Wiki alone, after 128 sessions: 48%. Search tool, no wiki: 53%. Wiki + search, after 128 sessions: 61%. The wiki chart's x-axis is a budget of 1M tokens per session, not measured spend. Wiki plus search also used about 20,000 fewer tokens per question. On 24 questions about a merger, Claude scored 87% with the wiki against 73% with search alone.

On a legal-brief task, several agents wrote to one shared table and overwrote each other; the brief built from that wiki met 41 of 57 graded facts. After the instructions changed so each agent wrote its own contract page quoting terms word for word, the brief met all 57.

When dreaming does not help: single-document answers (no clear gain over text search); over-detailed wikis (one reached 203 KB from a 115 KB corpus, 1.77 times its source); compute cost; error build-up. The Hacker News thread on the post (about 90 points when read) pushed in the same direction: several commenters read "dreaming" as a label for rewriting Markdown notes.
