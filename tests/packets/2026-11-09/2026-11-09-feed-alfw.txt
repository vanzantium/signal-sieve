COVERAGE — alfw.ai, "Anthropic's Dreaming Repairs Notes; Wiki Scores 48%"
URL: https://alfw.ai/article/anthropic-agent-memory-dreaming-wiki-48-percent/
Published: 2026-11-07. 5 min read. ANALYSIS.

Claude played Pokemon Red with a memory folder it could read and write during the run; the comparison covers one run per model, not an average.

Dreaming is a batch job. Between sessions, Claude re-reads transcripts of what it did, compares them with the notes it saved, corrects notes that do not match, merges duplicates, and sometimes rebuilds the notes into a linked wiki. No weights change. Nothing is learned in the training sense. The model is editing its own notebook, with the original record open beside it.

Pokemon: Claude saved the location of the PokeCenter at the entrance to Mt. Moon on the wrong side of the mountain. Acting on that note, it walked off a one-way ledge and landed back on the route it had come from, three times. After the third failure, Claude wrote that it would stop rather than keep looping. The test harness instructed it to continue, so it returned to Pewter City to heal and restock. The run eventually ended without reaching Cerulean City. A dreaming pass then checked the note against the session transcript, caught the error and rewrote it. With the corrected note, Claude went back into the cave and reached the city. One case proves a mechanism, not a rate. Anthropic does not say how often dreaming catches errors like this, or how often it introduces new ones.

Sonnet 3.7 saved almost everything: 413 files across 225 folders by about step 10,000, including a separate file for individual battles and items. It earned one badge. Fable 5 kept nine files in two folders, plus a single top-level file holding its current goal, its plan and its own rules for what to save. It earned four badges. Opus 5.5 kept a similarly small folder and finished the game. Read that as Anthropic presents it, with the limit stated in its own text: one run per model. A single run cannot separate a memory strategy from luck, route choices or the model itself, and Fable 5 is also simply a newer model than Sonnet 3.7. The comparison illustrates the costs of indiscriminate memory writing. It does not establish how much of the performance difference was caused by memory strategy rather than model capability or variation between runs.

CL-Bench 1.0 database task: newer models used memory to build a learning loop: record a failure, test a theory about it, keep the rule that survived. Opus 5 was the first to close that loop fully. But when Anthropic told the models to record only failures, both Opus 5 and Opus 4.7 lost much of the benefit memory had given them. A specific, plausible instruction made strong models worse. Weaker models needed the opposite: telling Sonnet 4.6 to read its memory before answering and to test its theories nearly doubled its score, a habit Sonnet 5 already has, reading its memory first in nine out of ten cases without being told.

Wiki numbers: Anthropic fed Claude about 350,000 internal files from Stainless, a company it acquired in May, roughly 420 million tokens, and had agents build a linked wiki over repeated dreaming sessions, then answer 25 questions from it. Across 25 evaluation questions, wiki-only performance increased from 13% to 48% of graded criteria as Anthropic expanded the wiki from two to 128 dreaming sessions. With both search and wiki available, performance rose from 54% to 61% over the same expansion. Search alone scored 53%. The final combined system therefore exceeded the search-only baseline by eight percentage points, while the incremental improvement from expanding the combined system's wiki was seven points. After 128 sessions of offline work, the wiki on its own still missed more than half of what the graders asked for. Search plus wiki also saved approximately 20,000 tokens per evaluation question, according to Anthropic. That is an inference-time saving, not a demonstrated reduction in total cost. Building and maintaining the wiki required up to 128 dreaming sessions, and the post does not provide a dollar-cost comparison or establish a break-even point.

In a separate evaluation involving 24 merger-document questions, Anthropic found a larger benefit on items requiring information from several documents or additional reasoning: 87% of graded criteria with the wiki, compared with 73% using search alone. On single-document questions it added nothing measurable, and in one case the wiki grew larger than the source documents, which is a summary that has stopped summarizing. In another documented repair pass, dreaming corrected nine links to a nonexistent wiki page and added three pages, including an index; Anthropic did not report a general link-repair success rate.

Anthropic is open about the remaining problems. Dreaming costs compute, checking every memory continuously is not practical, and how often to run it is an open tuning question. Anthropic warns that injecting incorrect memories into every new session can repeatedly propagate errors. Claude Code auto memory loads only the first 200 lines or 25 KB of MEMORY.md, using that header as an index. The post does not establish that this limit applies to every Claude agent or memory system. The word dreaming is optional.
