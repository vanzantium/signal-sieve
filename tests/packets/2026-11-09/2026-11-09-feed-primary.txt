Agent memory means knowledge Claude gains from experience and retains between sessions, saved as context it can read later. It excludes weight changes, in-context learning within a single conversation, and compaction. Researchers at Letta and UC Berkeley proposed sleep-time compute as a way for models to use idle time between interactions to reorganize existing context. Anthropic calls the agent version of this offline reorganization "dreaming": reflecting on logs to fix mistakes or produce new notes and representations.

Memory has four layers: searchable session transcripts at the bottom, memory notes Claude writes itself, memory representations such as linked wikis, and injected context loaded at the start of every session. Dreaming can operate across all four.

Memory is a prediction: writing down a rule predicts the pattern will recur; writing down a verified fact predicts a future session will want to rely on it without double-checking.

CL-Bench 1.0 database task (run on Claude Managed Agents; each question starts in a fresh session, with a persistent memory directory): Sonnet 4.6 generated theories about wrong answers but held scattered files of untested guesses. Opus 4.7 consolidated notes into a single reference document and marked facts checked or unconfirmed. Sonnet 5 marked answers confirmed after grading and wrote corrections when wrong. Opus 5 was the first to close the loop: entries included a rule, how it knew the rule was true, earlier answers, and warnings about traps. Opus 5.5 and Sonnet 5.5 also closed the loop and scored about the same as Opus 5 with memory, though their baselines without memory were slightly higher. Figure 3 alt text gives mean rewards, stateless baseline then memory store: Opus 5.5 0.655 and 0.838, Sonnet 5.5 0.644 and 0.833, Opus 5 0.564 and 0.828, Opus 4.7 0.383 and 0.700, Sonnet 5 0.306 and 0.610, Sonnet 4.6 0.330 and 0.364.

Pokemon Red: one run each of Sonnet 3.7 and Fable 5, about 10,000 steps in. Sonnet 3.7 wrote 413 memory files across 225 folders and earned one badge, logging every battle, item and character; around step 10,000 it started a fourth folder of master files and over 17 steps created six files, deleted nine, and took no game actions. Fable 5 wrote nine files in two folders plus a top-level global.md and earned four badges. Opus 5.5 kept a small folder of memory notes, rewrote them as it played, and beat the game.

Steering: telling Claude what memory is for, but not how to use it, works best for frontier models. With a rule "record only failures", both Opus 5 and Opus 4.7 lost much of the performance boost memory gave them. Sonnet 4.6 often did not read its memory files; prompting it to read memory before answering and test its theories nearly doubled its benchmark score. Sonnet 5 read its memory before answering 9 out of 10 times without being prompted; Sonnet 4.6 did so less than half the time.

Dreaming corrects memory: Claude wrote down incorrectly that the PokeCenter near Mt. Moon's entrance was on the east side, announced "Mt Moon is behind me", updated its notes "Mt Moon DONE", then fell off a one-way ledge three times and walked back to Pewter City; the run ended without reaching Cerulean City. Dreaming checked the note against the session transcript, caught the error and rewrote it; with the corrected note Claude went back into Mt. Moon and eventually reached Cerulean City.

Dreaming builds wikis: on a corpus of about 350,000 internal files, roughly 420M tokens, from Stainless (a software company Anthropic acquired in May), with 25 evaluation questions, Opus 5 agents ran 128 dreaming sessions. As dreaming scaled from two sessions to 128, performance on the 25 questions grew from 13% to 48% of graded criteria. With both search and wiki, aggregate score rose from 54% to 61%, compared with 53% for search alone. Search plus wiki saved about 20,000 tokens per question. On 24 merger questions, Claude scored 87% with the wiki versus 73% with search alone on items needing cross-document judgment or math. On one LAB task the wiki showed no clear gain; on another the wiki grew larger than the documents themselves (a 10-document, 115 KB corpus became a 68-page, 203 KB wiki).

Dreaming promotes notes: injected memories use tokens and a wrong note can be carried into every session; Claude Code auto memory loads only the first 200 lines or 25 KB of MEMORY.md as an index. On a LAB acquisition task, several agents writing to a shared table of contract terms overwrote each other and the brief included only 41 of the 57 facts (72%). After Claude reflected on failures and rewrote the instructions so each contract got its own page, written by a single agent quoting terms word for word, 100% of criteria could be met, up from 72%. A second dreaming pass found nine links to a missing page and repointed them, and added three new pages including an index.

Open questions: when to create memory, how to keep it up to date (dreaming costs compute; continuously checking all memories may not be practical), and whether transcript search should be the foundation. Cookbooks exist for getting started with dreaming and knowledge wikis.
